# Phase 07.1 Plan 06: FastGLiNER2 Concurrency Fan-Out Summary

**Order-preserving bounded thread-pool fan-out over FastGLiNER2 0.2.1 single-text CPU inference**

## Accomplishments

- Replaced the inert entity-extraction `batch_size` parameter with a bounded
  `ThreadPoolExecutor` concurrency width.
- Preserved one `predict_entities(str, labels)` call per text, input-order result alignment,
  result count, filtering, offset normalization, and error propagation.
- Proved the configured width is load-bearing: 12 texts at width 4 produce exactly 12
  single-text calls with an observed concurrent-call high-water mark of 4.
- Kept the current FastGLiNER2 model, CPU path, dependencies, and device claims unchanged.

## Task Commits

1. **Task 1 RED: Add failing concurrency contract tests** — `f5e513a` (test)
2. **Task 1 GREEN: Implement bounded order-preserving fan-out** — `683f271` (feat)
3. **Task 2: Document and pin GLINER_BATCH_SIZE semantics** — `012ed27` (docs)

The RED commit precedes the GREEN commit in repository history.

## Load-Bearing RED Evidence

Against the pre-change sequential implementation, the inverted-latency test failed at
`model.max_active == 4` because the observed high-water mark was `1`. After the GREEN change,
the same test passed with completions reversed by latency while returned results remained in
input order. This proves the test detects both missing fan-out and completion-order misalignment.

## Files Created/Modified

- `src/turing_agentmemory_mcp/gliner_provider_extraction.py` — Adds `_extract_one`, bounded
  thread-pool fan-out, input-order collection, and accurate FastGLiNER2 0.2.1 semantics.
- `tests/test_gliner_provider.py` — Covers order, count, width cap, sequential mode, empty input,
  single-string calls, filters, non-list results, and worker exceptions.

## Decisions Made

- **Concurrency, not model batching.** `fast_gliner==0.2.1` rejects multi-text
  `predict_entities` calls, so `GLINER_BATCH_SIZE` now bounds concurrent single-text calls.
- **Collect by input order.** `ThreadPoolExecutor.map` preserves alignment while still allowing
  faster inputs to finish first and propagating worker exceptions.
- **No performance verdict.** Plan 09 owns the same-code CPU throughput measurement and any later
  device decision. `PERF-04` remains pending.
- **Compose remains plan 05-owned.** Its bare `GLINER_BATCH_SIZE=1` assignment is unchanged and now
  selects sequential width 1; it may be reconsidered only after the planned measurement.
