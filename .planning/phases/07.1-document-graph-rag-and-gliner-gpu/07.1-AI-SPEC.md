## 1. System Classification

**System Type:** RAG

**Description:**
This amendment cuts the existing tenant-scoped RAG pipeline over to official
`Qwen/Qwen3-Embedding-0.6B` and `Qwen/Qwen3-Reranker-0.6B` safetensors behind the
application's existing provider-compatible HTTP contracts. Operators run one immutable provider
image as two internal CPU roles; the MCP application remains the only tenant-aware component.
Good behavior means query-aware, normalized 1024-dimensional vectors, probability-normalized
Qwen yes/no relevance scores over the bounded seed pool, reproducible artifacts, and no
application-facing schema change.

**Critical Failure Modes:**
1. A query is embedded without the fixed English retrieval instruction, or a document is
   incorrectly prefixed, silently destroying the asymmetric Qwen retrieval contract.
2. An embedding is non-finite, non-normalized, or not exactly 1024 values, or 768-dimensional
   indexes/data are reused after cutover.
3. Raw reranker logit differences are mistaken for probabilities, the `yes`/`no` direction is
   reversed, or incomplete/duplicate document indices are accepted.
4. A role auto-selects a GPU, loads both models, serves before its assigned model is ready, or
   exposes the tenant-blind provider outside the internal Compose network.
5. A mutable model revision/package/image or an unverified download changes behavior, or logs
   contain query/document text, vectors, credentials, or tenant identifiers.

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Developer tooling — multi-tenant agent-memory and cited-document retrieval infrastructure

**User Population:** AI application developers and integrators who consume retrieved evidence,
plus platform operators, SREs, and security reviewers who deploy and maintain the retrieval service

**Stakes Level:** Critical

**Output Consequence:** Ranked memories and cited document chunks become untrusted evidence in a
downstream agent's context. Wrong, stale, poisoned, or foreign-tenant evidence can contaminate an
answer or tool decision; a faulty cutover or rebuild can also make durable runtime memory
irrecoverable.

### What Domain Experts Evaluate Against

**Dimension: Tenant-bound evidence**

Good (domain expert would accept): Every result, citation, graph hop, job, cache entry, and rebuild
belongs to the exact caller-bound, non-empty `user_identifier`; adversarial cross-tenant queries
return no evidence, including under concurrency and physical database misrouting.

Bad (domain expert would flag): Any result crosses tenant boundaries, a model or document can
select the tenant, an empty identifier is accepted, or physical separation is treated as a
substitute for the explicit tenant predicate and binding check.

Stakes: Critical

Source: Project invariants in `CLAUDE.md`, `CONTRIBUTING.md`, and `docs/architecture.md`; OWASP
Multi-Tenant Application Security and RAG Security guidance.

**Dimension: Answer-bearing evidence at the top**

Good (domain expert would accept): On a labeled product query, the returned top-k contains the
specific memory or all required supporting chunks, with the correct document, chunk/page, and
source provenance. For a multi-hop query, all pre-labeled bridging passages are present; common
single-passage queries do not lose useful evidence to entity hubs or graph-expanded noise.

Bad (domain expert would flag): The needed passage is absent or crowded out, a citation points to
the wrong source, or a superficially related hub/neighbor ranks above the evidence needed to
answer the query.

Stakes: High

Source: Phase 07.1 `ROADMAP.md` and `07.1-CONTEXT.md` efficacy gate; RAG evaluation research on
retrieval relevance, coverage, noise robustness, and sufficient context.

**Dimension: Canonical continuity through cutover**

Good (domain expert would accept): At the authorized DEV-only cutover, every retained memory and
document chunk is rebuilt into one verified Qwen3 1024-dimensional vector space from canonical
ArcadeDB data, while the pseudonymous registry remains consistent durable control state. A backup
exists or irrecoverable runtime-memory loss is explicitly accepted; source, Git, `.planning`,
configuration, and secrets remain outside the destructive scope.

Bad (domain expert would flag): Old and new vector spaces coexist, tenant counts or provenance
silently change, the registry and tenant databases disagree, an unbacked working-memory store is
destroyed without warning, or the reset reaches an excluded asset.

Stakes: Critical

Source: `07.1-AI-SPEC.md` cutover contract; `CLAUDE.md`, `README.md`, and `docs/operations.md`
canonical-state, backup, and vector-recovery rules.

**Dimension: Evidence trust and provenance**

Good (domain expert would accept): Retrieved text remains clearly delimited and subordinate
untrusted evidence, citations remain attached to stable source IDs, and downstream tool actions
are independently authorized and validated. Logs and provider telemetry remain content-free.

Bad (domain expert would flag): Text inside a memory or document is executed as an instruction,
source attribution is lost or altered, a retrieved tenant identifier controls scope, or queries,
documents, vectors, credentials, or raw identifiers enter shared logs.

Stakes: Critical

Source: `docs/security.md` and `docs/architecture.md`; OWASP LLM01 Prompt Injection, LLM08 Vector
and Embedding Weaknesses, and RAG Security guidance.

**Dimension: Operationally honest product proof**

Good (domain expert would accept): A fixed real corpus and query set shows searchable cited
chunks, retrieval quality, p50/p95 latency, throughput, failures, and variance under matched
provider revisions, dimensions, hardware, and concurrency. Generic Qwen benchmarks and wire
contract tests are treated as component gates, not proof that AgentMemory retrieves better
evidence.

Bad (domain expert would flag): A job reports success without searchable canonical chunks, text
is silently truncated or a provider silently falls back, or a model-card score, one favorable
run, or mismatched configurations are reported as a product-quality win.

Stakes: High

Source: `README.md`, `docs/performance.md`, and `CONTRIBUTING.md`; research showing that standalone
retrieval relevance labels and component scores can correlate weakly with downstream RAG utility.

### Known Failure Modes in This Domain

1. **Tenant escape through retrieval plumbing:** a missing predicate, stale tenant binding,
   shared cache/job context, or unscoped graph traversal returns another tenant's memory or
   document chunk even though each tenant normally has a separate database.
2. **Context contamination:** name-only homographs, over-connected entity hubs, stale chunks, or
   poisoned document instructions crowd out the required evidence and steer a downstream agent
   toward an unsupported answer or unauthorized tool action.
3. **Cutover split-brain or destructive loss:** 768- and 1024-dimensional projections are mixed,
   only part of the corpus is rebuilt, registry/database state diverges, or DEV runtime memories
   with no external source are irrecoverably removed without a verified backup or explicit
   acceptance.
4. **False-green pipeline:** embeddings and reranker responses satisfy their schemas or generic
   benchmarks while real product queries regress; whole-document extraction fails before
   chunking, a job commits only part of its chunks, citations detach, or CPU latency makes the
   retrieval path operationally unusable.

### Regulatory / Compliance Context

No regulated industry vertical or deployment-specific high-risk statutory classification was
identified. The directly relevant baseline is security and privacy for a durable multi-tenant
state service: bind authenticated principals to allowed tenant identifiers, enforce isolation at
every retrieval layer, preserve provenance, treat retrieved content as untrusted, minimize
sensitive telemetry, and make deletion/backup retention behavior explicit.

If a deployment stores EU personal data, GDPR obligations are data- and controller-dependent;
Articles 5, 25, and 32 make data minimization/storage limitation, data protection by design, and
appropriate security relevant. The DEV-only rebuild authorization does not expand its target:
runtime loss must be backed up or explicitly accepted, and source/Git/`.planning`/configuration/
secrets remain excluded.

## 2. Framework Decision

**Selected Framework:** Direct provider adapter using Sentence Transformers 5.5.1 with the PyTorch CPU backend

**Version:** Sentence Transformers 5.5.1, Transformers 5.14.1,
PyTorch 2.13.0+cpu, Hugging Face Hub 1.25.1, safetensors 0.8.0, and Pydantic
2.13.4

**Rationale:**
Sentence Transformers has official integration paths for both selected Qwen models:
`SentenceTransformer.encode()` exposes explicit device, normalization, and revision controls,
while `CrossEncoder.predict()` exposes the rerank logits and activation. A thin adapter therefore
preserves the repository's existing `/v1/embeddings` and `/v1/rerank` clients without adding a
second orchestration framework or tenant-aware provider state. One package-identical image can be
run with two role entry points, so each CPU process loads only its assigned 0.6B model and can be
scaled, health-checked, and benchmarked independently.

**Version and artifact lock:** Build from the repository's already-pinned
`python:3.12-slim@sha256:423ed6ab25b1921a477529254bfeeabf5855151dc2c3141699a1bfc852199fbf`.
Resolve all Python transitive dependencies into a hash-checked lock; the direct versions above
are not ranges. Pin the embedding repository to
`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`
(`model.safetensors` SHA-256
`0437e45c94563b09e13cb7a64478fc406947a93cb34a7e05870fc8dcd48e23fd`) and the
reranker repository to `e61197ed45024b0ed8a2d74b80b4d909f1255473`
(`model.safetensors` SHA-256
`27cd75a405b9c1b46b59abfd88aaa209e6fed2a1972cde9b70e7659537c5e65b`).
These revisions and LFS hashes were validated against the official model APIs on 2026-07-29.
Provisioning must verify a committed SHA-256 manifest for the complete downloaded snapshot before
atomic rename. Compose must reference the built provider image by the actual verified digest
emitted by the build, never by a mutable tag alone.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Hybrid: Hugging Face Text Embeddings Inference 1.9.3 CPU plus the Sentence Transformers adapter | Retained only as an embedding-throughput fallback; it does not provide the selected Qwen3 reranker contract. |
| llama.cpp/GGUF for both roles | The selected artifacts are official safetensors, and exact Qwen3 reranker prompt plus yes/no score parity has not been proved for the current llama.cpp path. |
| Raw Transformers adapter | It can implement the models, but would duplicate last-token pooling, prompt formatting, and yes/no logit extraction already covered by the official Sentence Transformers integrations. |
| One process loading both models | It couples failure/scaling domains and doubles resident model memory for requests that need only one role. |

**Vendor Lock-In Accepted:** Partial — Qwen model semantics are locked, while the internal HTTP transport remains provider-compatible.

### Entry Point Pattern
```python
import math
import os
from typing import cast

import torch
from sentence_transformers import CrossEncoder, SentenceTransformer

EMBED_MODEL = "Qwen/Qwen3-Embedding-0.6B"
EMBED_REVISION = "97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3"
RERANK_MODEL = "Qwen/Qwen3-Reranker-0.6B"
RERANK_REVISION = "e61197ed45024b0ed8a2d74b80b4d909f1255473"
RERANK_INSTRUCTION = (
    "Given a user query, retrieve relevant passages from an agent memory "
    "and document corpus"
)


def load_assigned_role() -> SentenceTransformer | CrossEncoder:
    role = os.environ["QWEN_ROLE"]
    device = os.environ["QWEN_DEVICE"]
    if device != "cpu":  # The development reference path never auto-detects a device.
        raise RuntimeError("QWEN_DEVICE must be cpu for this image profile")
    if role == "embedding":
        return SentenceTransformer(
            EMBED_MODEL,
            revision=EMBED_REVISION,
            device=device,
            backend="torch",
            trust_remote_code=False,
        )
    if role == "rerank":
        return CrossEncoder(
            RERANK_MODEL,
            revision=RERANK_REVISION,
            device=device,
            backend="torch",
            trust_remote_code=False,
            max_length=8192,
            prompts={"agentmemory": RERANK_INSTRUCTION},
            default_prompt_name="agentmemory",
            activation_fn=torch.nn.Identity(),
        )
    raise RuntimeError(f"unsupported QWEN_ROLE: {role}")


MODEL = load_assigned_role()  # Exactly one branch imports model weights into this process.


def embed_wire_inputs(inputs: list[str], batch_size: int = 16) -> list[list[float]]:
    model = cast(SentenceTransformer, MODEL)
    vectors = model.encode(
        inputs,  # Queries already carry the query-only wire prefix; documents do not.
        batch_size=batch_size,
        device="cpu",
        normalize_embeddings=True,
        precision="float32",
        convert_to_numpy=True,
        show_progress_bar=False,
    )
    output = [row.astype("float32").tolist() for row in vectors]
    if any(len(row) != 1024 or not all(math.isfinite(value) for value in row) for row in output):
        raise RuntimeError("invalid embedding output")
    return output


def rerank(query: str, documents: list[str], batch_size: int = 4) -> list[float]:
    model = cast(CrossEncoder, MODEL)
    raw_logit_differences = model.predict(
        [(query, document) for document in documents],
        batch_size=batch_size,
        activation_fn=torch.nn.Identity(),
        convert_to_numpy=True,
        show_progress_bar=False,
    )
    # Qwen defines the score as the yes/no logit difference. Sigmoid is P(yes).
    probabilities = torch.sigmoid(
        torch.as_tensor(raw_logit_differences, dtype=torch.float64)
    ).tolist()
    if not all(math.isfinite(score) and 0.0 <= score <= 1.0 for score in probabilities):
        raise RuntimeError("invalid rerank output")
    return probabilities
```

The HTTP boundary maps only `embed_wire_inputs` to `/v1/embeddings` in the embedding role and
only `rerank` to `/v1/rerank` in the rerank role. A wrong-path request returns 404/405; it must
never lazy-load the other model.

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `SentenceTransformer` | Bi-encoder wrapper with pinned Hub revision, explicit backend/device, batching, and L2 normalization | Produce query and canonical document vectors in one fixed 1024-dimensional space |
| `CrossEncoder` | Pairwise query/document scorer | Score only the bounded retrieval seed pool before the existing rerank guard |
| Query/document asymmetry | Queries carry one fixed English `Instruct`/`Query` prefix; documents are raw | Configure `EMBED_QUERY_PREFIX` while leaving `EMBED_DOCUMENT_PREFIX` empty |
| Raw logit difference | Qwen's Sentence Transformers reranker output before activation | Apply sigmoid exactly once to expose a stable `[0,1]` `relevance_score` |
| Role-pinned process | One immutable image started as either `embedding` or `rerank` | Keep model memory, health, scaling, and failures independent |

### Common Pitfalls
1. Leaving `device=None` lets Sentence Transformers auto-detect hardware. Require
   `QWEN_DEVICE=cpu` and expose the selected device in health metadata.
2. Calling `prompt_name="query"` for every embedding prefixes documents too; calling plain
   `encode()` for every input leaves queries uninstructed. The unchanged wire schema requires
   the application client to prefix queries only.
3. `normalize_embeddings` defaults to false and `truncate_dim` can silently change vector
   width. Set normalization explicitly and reject anything other than 1024 finite values.
4. Qwen reranker `CrossEncoder.predict()` returns raw logit differences by default. Do not expose
   them as probabilities or apply sigmoid twice; sort on one sigmoid-normalized `P(yes)` scale.
5. Loading from `main`, trusting remote code, sharing a mutable cache without a manifest, or
   logging request bodies makes a nominally local provider non-reproducible or unsafe.

## 4. Implementation Guidance

**Model Configuration:**

| Role | Model / revision | Required behavior |
|------|------------------|-------------------|
| Embedding | `Qwen/Qwen3-Embedding-0.6B@97b0c614...` | `backend="torch"`, `device="cpu"`, float32, L2-normalized, full 1024 dimensions, batch start at 16 and benchmark before tuning |
| Rerank | `Qwen/Qwen3-Reranker-0.6B@e61197ed...` | `device="cpu"`, `max_length=8192`, batch start at 4, fixed English retrieval instruction, raw logit difference transformed once with sigmoid |

These are encoder/scorer models: temperature and generation `max_tokens` do not exist. Set
tokenizer limits explicitly instead. The advertised model context is 32K, but the CPU reference
uses an explicit 8192-token ceiling pending measured evidence for a larger budget.

**Core Pattern:**

1. Configure the existing application client with
   `EMBED_QUERY_PREFIX="Instruct: Given a user query, retrieve relevant passages from an agent memory and document corpus\nQuery:"`
   and `EMBED_DOCUMENT_PREFIX=""`. `embed_query()` sends the English instruction; all ingestion,
   rebuild, memory, entity, fact, community, and chunk document embeddings remain unprefixed.
2. The embedding role validates the requested model and optional `dimensions` (absent or 1024),
   encodes the batch with L2 normalization, then validates count, order, finite values, dimension,
   and unit norm before serialization.
3. The application retrieves in the new 1024-dimensional indexes, forms the existing bounded
   seed pool, and sends at most 50 query/document pairs to the rerank role.
4. The rerank role uses Qwen's fixed yes/no template via `CrossEncoder`, keeps the raw logit
   difference internal, emits `sigmoid(logit_difference)` as `relevance_score`, and returns one
   unique index per input. The existing application-side guard/fallback remains authoritative.

**Tool Use:**

The application-facing contracts stay unchanged:

| Endpoint | Request | Success response |
|----------|---------|------------------|
| `POST /v1/embeddings` | `model` must equal the embedding model; `input` is a string or 1-128 strings; optional `dimensions` is 1024 only | OpenAI list object with one ordered `{object:"embedding", index, embedding}` row per input; every vector has exactly 1024 finite normalized floats |
| `POST /v1/rerank` | exact reranker `model`, non-empty `query`, and 1-50 bounded `documents` | `{model, results:[{index, relevance_score}]}` sorted descending; indices are unique/complete and scores are finite probabilities in `[0,1]` |

Return the existing `{"error":{"code":<http-status>,"message":"<content-free-code>"}}` shape for
invalid requests. Reject model mismatch, wrong role, empty/oversized input, non-1024 dimensions,
and malformed output; never silently coerce them.

Compose runs one digest-pinned image twice with `QWEN_ROLE=embedding|rerank` and
`QWEN_DEVICE=cpu`. Each service receives only its assigned model revision and verified snapshot,
uses an independent health check that performs a tiny semantic contract probe, is reachable only
through `expose`, and publishes no host port. Provider logs contain request ID, role, model
revision, batch/document and token/byte counts, queue/inference/total milliseconds, status, and
error code only--never text, vectors, credentials, or tenant identifiers. TEI 1.9.3 remains an
embedding-only fallback and may replace this embedding role only after an apples-to-apples CPU
throughput and retrieval-parity result; it does not alter the selected reranker.

**State Management:**

The provider is tenant-blind and stateless apart from immutable in-memory weights and a
read-only, manifest-verified model snapshot. It accepts no `user_identifier` field and owns no
tenant cache. ArcadeDB remains canonical; all tenant predicates and stable IDs stay in the MCP
application. The embedding revision, instruction version, normalization flag, dimension, and
artifact hashes must be recorded in runtime health and benchmark artifacts.

The 1024-dimensional cutover is a schema/data migration: existing 768-dimensional indexes and
vectors cannot be read, mixed, copied, or benchmarked as if compatible. Reset/rebuild ordering,
rollback, and tenant migration are execution-plan responsibilities, but readiness must fail if
the configured store dimension, index manifest, provider health dimension, and model revision do
not all agree.

**Context Window Strategy:**

Keep ingestion chunking upstream of the provider; never rely on silent tokenizer truncation to
make a canonical document fit. Reject or visibly count truncation at the adapter boundary.
Embedding batches are at most 128 inputs. Preserve the existing rerank caps of 2048 characters
per document, 32768 total UTF-8 bytes, 8192 estimated tokens, and 50 candidates, then enforce the
exact tokenizer ceiling server-side. Rerank only the original dense/lexical/fused seed pool,
never graph-expanded neighbors. If a retrieval context later exceeds the answer model's window,
select by rerank order, keep citation-bearing whole chunks, and truncate the lowest-ranked tail
rather than clipping evidence mid-chunk.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs with Pydantic

```python
import math
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, field_validator, model_validator


class EmbeddingRow(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    object: Literal["embedding"]
    index: int = Field(ge=0)
    embedding: list[float] = Field(min_length=1024, max_length=1024)

    @field_validator("embedding")
    @classmethod
    def finite_unit_vector(cls, vector: list[float]) -> list[float]:
        if not all(math.isfinite(value) for value in vector):
            raise ValueError("embedding contains a non-finite value")
        norm = math.sqrt(math.fsum(value * value for value in vector))
        if not math.isclose(norm, 1.0, rel_tol=1e-4, abs_tol=1e-4):
            raise ValueError("embedding is not L2-normalized")
        return vector


class EmbeddingUsage(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    prompt_tokens: int = Field(ge=0)
    total_tokens: int = Field(ge=0)


class EmbeddingResponse(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    object: Literal["list"]
    model: Literal["Qwen/Qwen3-Embedding-0.6B"]
    data: list[EmbeddingRow] = Field(min_length=1, max_length=128)
    usage: EmbeddingUsage

    @model_validator(mode="after")
    def ordered_indices(self) -> "EmbeddingResponse":
        if [row.index for row in self.data] != list(range(len(self.data))):
            raise ValueError("embedding indices are not ordered and complete")
        return self


class RerankRow(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    index: int = Field(ge=0)
    relevance_score: float = Field(ge=0.0, le=1.0, allow_inf_nan=False)


class RerankResponse(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    model: Literal["Qwen/Qwen3-Reranker-0.6B"]
    results: list[RerankRow] = Field(min_length=1, max_length=50)

    @model_validator(mode="after")
    def complete_descending_result(self) -> "RerankResponse":
        indices = [row.index for row in self.results]
        if set(indices) != set(range(len(indices))) or len(indices) != len(set(indices)):
            raise ValueError("rerank indices are not unique and complete")
        scores = [row.relevance_score for row in self.results]
        if scores != sorted(scores, reverse=True):
            raise ValueError("rerank results are not sorted")
        return self


def validate_wire_responses(
    embedding_json: bytes,
    rerank_json: bytes,
    expected_embedding_count: int,
    expected_rerank_count: int,
) -> tuple[EmbeddingResponse, RerankResponse]:
    embedded = EmbeddingResponse.model_validate_json(embedding_json)
    reranked = RerankResponse.model_validate_json(rerank_json)
    if len(embedded.data) != expected_embedding_count:
        raise ValueError("embedding response count mismatch")
    if len(reranked.results) != expected_rerank_count:
        raise ValueError("rerank response count mismatch")
    return embedded, reranked
```

Use these schemas on serialization in the provider and on parsing in contract tests/application
boundary code. Transient HTTP 429/5xx/network failures retain the existing maximum of three
attempts with 0.5s then 1.0s backoff. A schema, dimension, index, finite-value, normalization, or
score-range failure receives zero retries because it is a deterministic provider defect. Log
only request ID, role/revision, counts/timings, error code and failing field. Embedding failures
surface and prevent a write/search with a corrupt vector; rerank failures surface as the existing
content-free `invalid_response`/`provider_error` status and preserve seed order.

### Async-First Design

Sentence Transformers inference is synchronous and CPU-bound. An async HTTP boundary must put
each role behind a bounded semaphore/queue and `await asyncio.to_thread(...)` or a dedicated
executor; it must not run `encode()`/`predict()` on the event loop. Do not call `asyncio.run()`
from an already-running FastMCP/server loop. Start with one in-flight model call per role because
PyTorch already uses CPU threads, then benchmark before raising concurrency to avoid thread
oversubscription. Embedding and rerank responses are awaited atomically so the complete result
can be validated; streaming is for a later generative answer UX, never for partial vectors or a
partially ranked list.

### Prompt Engineering Discipline

Keep the English embedding instruction and rerank instruction as immutable, versioned
configuration owned by the application/provider. Append the untrusted user query only in the
query slot and documents only in the document slot; retrieved text cannot choose an instruction,
model, role, revision, or tenant. Documents remain unprefixed for embeddings. Few-shot examples
are unnecessary for these trained encoder/scorer models and would consume the CPU token budget;
any future dynamic examples belong in the downstream answer generator and must be retrieved as
untrusted evidence. These endpoints do not generate tokens, so `max_tokens` is inapplicable;
explicit `max_length`, batch, byte, document, and candidate limits are mandatory. Any later
generative RAG call must set its own finite `max_tokens` in that model's contract.

### Context Window Management

Use page/citation-aware upstream chunks that fit the explicit 8192-token CPU reference ceiling.
Measure exact tokenizer counts at the adapter; reject or report truncation instead of silently
changing canonical document evidence. At retrieval time, over-fetch bounded dense/lexical
candidates, rerank at most 50, then pack complete top-ranked chunks until the downstream answer
budget is reached. Preserve citations and remove the lowest-ranked tail first. The advertised
32K model window is a ceiling, not a target for every CPU call.

### Cost and Latency Budget

The self-hosted provider has zero per-call API fee; compute cost must be reported from the target
CPU rather than invented. The expected retrieval unit is one query embedding plus at most 50
rerank pairs; ingestion uses embedding batches of at most 128. Record warm/cold p50/p95 wall time,
CPU-seconds, peak RSS, and safe concurrency. The estimate is
`monthly_calls * (embed_seconds + rerank_seconds) * host_currency_per_hour /
(3600 * measured_safe_concurrency)`. Cutover fails if p95 exceeds the existing 60s embedding or
30s rerank client ceilings, or if the later matched retrieval benchmark regresses its committed
latency gate.

Cache immutable model snapshots by revision and exact embeddings by a content-free key containing
model revision, instruction version, normalization, dimension, and text hash. Any application
result cache must also be tenant-scoped and retention-aware. Semantic query/result caching starts
disabled: it may be enabled only after tenant-isolation tests and a no-regression retrieval eval,
because near queries can require different evidence. Do not route embedding calls to a cheaper
model--that would mix vector spaces. These selected 0.6B models are already the low-cost
embedding/rerank tier; cheaper classification or summarization routing belongs only to a separate
downstream generative pipeline.

## 5. Evaluation Strategy

This amendment is evaluated at two boundaries: first the tenant-blind Qwen provider component,
then the tenant-aware AgentMemory product. Generic model-card scores are not acceptance evidence.
All product comparisons use frozen inputs, real non-stub providers, verified model/corpus
digests, and machine-readable JSON. There is no generative answer or subjective style dimension
in this cutover, so no LLM judge is used.

The critical failures under evaluation are:

1. query/document embedding asymmetry, width, finiteness, or normalization is wrong;
2. reranker yes/no semantics, normalization, indices, or stable ordering is wrong;
3. a provider/API pass hides a regression on real Italian retrieval or the committed E2E gates;
4. provider content enters telemetry or application retrieval crosses a tenant boundary;
5. mutable or mismatched model/image artifacts serve while reporting healthy; and
6. the destructive DEV rebuild mixes vector spaces, loses unacknowledged canonical memory, or
   touches an asset outside its approved target manifest.
