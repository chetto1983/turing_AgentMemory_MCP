# Phase 07.1 Plan 08: Per-Chunk GLiNER Extraction Summary

**Bounded GLiNER HTTP sub-batches and per-chunk entity metadata eliminate whole-document 400s while preserving redaction, stored-text embeddings, and atomic document writes**

## Performance

- **Duration:** 14 min
- **Started:** 2026-07-29T13:08:12Z
- **Completed:** 2026-07-29T13:22:14Z
- **Tasks:** 2 TDD tasks
- **Files modified:** 5 production/test files

## Accomplishments

- Sourced `MAX_TEXTS` directly from the sidecar extraction contract and split only non-blank
  inputs into bounded requests while scattering results back to their original slots.
- Reordered document processing to run governance redaction over the whole text before hashing
  and chunking, preventing a secret spanning a raw chunk boundary from escaping.
- Processed the chunk list once through `_process_texts_for_storage`, persisted each returned
  metadata object on its owning Chunk, and kept Document metadata free of extraction output.
- Moved `_embed_many` below per-chunk processing so every vector describes the exact text stored
  in its Chunk row.
- Preserved the single `_write_many` transaction for the Document, all Chunks, and all edges.

## Decisions Made

- **Per-chunk metadata, no document union.** `search_documents` reads Chunk `metadata_json`; no
  live reader of `Document.metadata_json["entity_extraction"]` was found. A document-level union
  would be an unmaintained duplicate projection, so Document metadata carries only caller and
  governance-redaction data.
- **Redaction remains whole-text first.** `PatternRedactor` substitutes secrets with tokens such
  as `[API-KEY]`. Those tokens do not match any `SECRET_PATTERNS`, so the later per-chunk pass is
  text-idempotent; `_redact_for_storage` starts from the existing metadata dict, preserving the
  first pass's redaction evidence.
- **Embedding moved.** `_embed_many` now consumes the returned processed chunk texts because
  entity processing may redact text. Tests assert the embedder input equals every committed
  Chunk `text` value.
- **Sidecar authority stays singular.** The client imports `MAX_TEXTS`; the sidecar's
  `MAX_TEXTS = 256` and `MAX_TEXT_CHARS = 16_384` remain unchanged.
